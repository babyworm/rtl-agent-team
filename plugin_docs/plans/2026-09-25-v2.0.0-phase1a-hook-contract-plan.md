# Phase 1a — Hook Output Contract and Stop-Gate Breaker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the plugin's Stop gates and PreToolUse denies actually keep Claude working (or hand the decision to the user) instead of silently ending the turn, and bound every gate so it cannot loop without progress.

**Architecture:** `hooks/lib/hook-output-util.sh` emits the three shapes Claude Code honors — Stop block, Stop notice, PreToolUse deny — and never `continue:false`. A new `hooks/lib/stop-budget-util.sh` gives each Stop gate a per-chain budget keyed on a progress fingerprint: the gate blocks until it has blocked `RAT_STOP_BLOCK_LIMIT` (default 3) times in one continuation chain without progress, then lets Claude stop with a notice to the user. Stages whose next step is a user decision emit the notice directly. The two dead spawn hooks move from `TaskCreate` to `Agent`.

**Tech Stack:** POSIX sh hooks (`hooks/*.sh`, invoked with `sh`), pytest unit tests, Claude Code CLI 2.1.282 for the live check.

**Parent:** `2026-09-25-v2.0.0-roadmap.md` Phase 1 (findings F1, F8). Sibling plans: 1b slash-command parity (F2), 1c consented template install and update channel (#8, F4), 1d runner-written verification evidence (F3).

```sh
#!/bin/sh
# hook-output-util.sh — Shared hook JSON output helpers.
# Requires: json-util.sh sourced and parser detected.
#
# Output contract (Claude Code hooks reference; verified live on CLI 2.1.282):
# a gate never sets the continue field to false. That field takes precedence
# over a Stop block and a PreToolUse deny, ends the turn, and drops the reason.
#   Stop block   {"decision":"block","reason":…}  Claude receives the reason and keeps working.
#   Stop notice  {"systemMessage":…}              Claude stops; the user sees the message.
#   Deny         hookSpecificOutput.permissionDecision "deny"  Only that tool call is refused.

# Emit a continue response with optional additionalContext message, then exit 0.
# Usage: emit_continue "message"   or   emit_continue ""
emit_continue() {
  _EC_MSG="$1"
  if [ -n "$_EC_MSG" ]; then
    printf '{"continue":true,"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":"%s"}}' "$(jsonu_escape "$_EC_MSG")"
  else
    printf '{"continue":true}'
  fi
  exit 0
}

# Refuse one tool call and give Claude the reason, then exit 0.
# Usage: emit_block "reason message"
emit_block() {
  _EB_MSG="$1"
  printf '{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"%s"}}' "$(jsonu_escape "$_EB_MSG")"
  exit 0
}

# Keep Claude working: block the stop and return the reason to Claude, then exit 0.
# Stop gates call this through stopu_gate (stop-budget-util.sh) so they cannot loop.
# Usage: emit_stop_block "reason message"
emit_stop_block() {
  _ESB_MSG="$1"
  printf '{"decision":"block","reason":"%s"}' "$(jsonu_escape "$_ESB_MSG")"
  exit 0
}

# Let Claude stop and show a message to the user, then exit 0.
# Use when the next step is the user's decision (waivers, approvals, escalations).
# Usage: emit_stop_notice "message for the user"
emit_stop_notice() {
  _ESN_MSG="$1"
  printf '{"systemMessage":"%s"}' "$(jsonu_escape "$_ESN_MSG")"
  exit 0
}

# Emit a PostToolUse continue response (no additionalContext), then exit 0.
# Usage: emit_post_continue
emit_post_continue() {
  printf '{"continue":true}'
  exit 0
}
```

```sh
#!/bin/sh
# stop-budget-util.sh — no-progress breaker shared by the Stop gates.
# Requires: json-util.sh and hook-output-util.sh sourced.
#
# A Stop gate blocks (Claude keeps working) until it has blocked
# RAT_STOP_BLOCK_LIMIT times (default 3) in one continuation chain while its
# progress fingerprint stayed the same; then it lets Claude stop and shows a
# notice to the user instead. A chain starts at the first Stop after a user
# turn (stop_hook_active false) and lasts while Stop blocks keep the turn
# going. A changed fingerprint means the gate's condition moved, which restarts
# the count. RAT_STOP_BLOCK_LIMIT=0 turns every block into a notice.

# Print "true" when this Stop continues a chain started by an earlier block.
# Usage: stopu_chain_active "$INPUT"
stopu_chain_active() {
  if printf '%s' "$1" | grep -Eq '"stop_hook_active"[[:space:]]*:[[:space:]]*true'; then
    printf 'true'
  else
    printf 'false'
  fi
}

# Reduce arbitrary text to a one-token progress fingerprint.
# Usage: FP=$(stopu_fingerprint "text")
stopu_fingerprint() {
  printf '%s' "$1" | cksum | awk '{print $1 "-" $2}'
}

# Block, or hand over to the user once the chain's budget is spent. Always exits.
# Usage: stopu_gate <gate-id> <state-dir> <chain-active> <fingerprint> <reason> <notice> [limit]
stopu_gate() {
  _SG_FILE="$2/stop-budget-$1.txt"
  _SG_LIMIT=${7:-${RAT_STOP_BLOCK_LIMIT:-3}}
  case "$_SG_LIMIT" in ''|*[!0-9]*) _SG_LIMIT=3 ;; esac
  _SG_COUNT=0
  if [ "$3" = "true" ] && [ -f "$_SG_FILE" ]; then
    _SG_COUNT=$(sed -n '1p' "$_SG_FILE")
    case "$_SG_COUNT" in ''|*[!0-9]*) _SG_COUNT=0 ;; esac
    [ "$(sed -n '2p' "$_SG_FILE")" = "$4" ] || _SG_COUNT=0
  fi
  if [ "$_SG_COUNT" -ge "$_SG_LIMIT" ]; then
    emit_stop_notice "$6"
  fi
  printf '%s\n%s\n' "$((_SG_COUNT + 1))" "$4" > "$_SG_FILE" 2>/dev/null
  emit_stop_block "$5"
}

# Forget a gate's budget once its condition is satisfied.
# Usage: stopu_clear <gate-id> <state-dir>
stopu_clear() {
  rm -f "$2/stop-budget-$1.txt" 2>/dev/null
}
```
