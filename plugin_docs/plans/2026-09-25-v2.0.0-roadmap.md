## 2. Findings beyond the report

F1–F4 undermine the enforcement model the plugin is built on; they come before any other v2 work.

- **F1. Stop gates cannot block.** `emit_stop_block` (`hooks/lib/hook-output-util.sh:27-31`) emits `{"continue":false,"decision":"block",…}`. Per the hooks reference, `continue: false` takes precedence and Claude stops. `rtl-verify-stop-gate.sh` (Rule 5), `rtl-skill-completion-gate.sh`, `stop-gate.sh` and `rtl-p6-cascade-gate.sh` therefore end the turn instead of returning the reason to Claude; only `rtl-coverage-exclusion-gate.sh` uses the working shape. 39 assertions in `tests/unit/test_hooks.py` and `plugin_docs/hook-development-guide.md:86` pin the wrong shape. `emit_block` (PreToolUse deny) also sets `continue:false`, halting the whole turn.
- **F2. Typed slash commands bypass every PreToolUse(Skill) hook.** They fire `UserPromptExpansion` (`expansion_type: "slash_command"`, `command_name`), which `hooks.json` does not register, so the completion loop, compliance state, spawn manifest and P5B entry block never engage.
- **F3. Rule 5 evidence is self-attested.** The agent `touch`es `.rat/state/rtl-verify-done` (`skills/rtl-orchestrate/SKILL.md:438`); the PPA smoke gate trusts `| tee` without `pipefail` (`ppa-optimizer-dc-orchestrator.md:240-249`).
- **F4. Fixes do not reach existing projects.** Stale `rat-version` markers (`run_lint.sh`/`run_cdc.sh` 0.7.7 after 12 content commits, `run_syn.sh` 0.11.3 after 7, none in `run_sim.sh`) and no caller passing `--update`.
- **F5. The Docker fallback cannot work.** Host paths are passed unchanged into a container that mounts the project at `/workspace`; `run_syn.sh` exits 127 before `run_tool`; the Makefile sources the bash-only library under `/bin/sh`.
- **F6. `env_source` and `tools.*.path` are detection-only.** No wrapper, Makefile rule or hook reads `rat_config.json`.
- **F7. Tool preferences are not honored downstream.** `SIM=verilator` hard-coded in the func-verify orchestrator; 11 agents hard-code Verilator and 2 Yosys; no route from `preferences.simulator` to UVM; preferences never refresh.
- **F8. Two hooks never fire.** `rtl-spawn-context.sh` and `rtl-audit-spawn-complete.sh` match `TaskCreate` but read the `Agent` tool's `subagent_type`.
- **F9. SpyGlass gaps beyond #10/#11.** `+incdir+`/`+define+` dropped, nested `-f` aborts, `run_goal` violations never fail the run, and `sg_shell` is ranked first for lint and CDC.
- **F10. Exit-status trust is simulator-wide.** Questa `-do "run -all; quit -f"` returns 0; `run_sim.sh` parses no logs.
- **F11. Maintainer environment.** The installed plugin here is 0.10.4 (phantom `lib:*` agents; 69/97 skills listed without a description). oh-my-claudecode 4.13.4 re-invokes finished subagents from its SubagentStop hook.

## 3. Principles for v2.0.0

1. **Evidence over attestation.** Gate verdicts are computed by code from artifacts (logs, result JSON, content hashes). Prompts consume verdicts; they do not produce them.
2. **One execution choke point.** Every tool and simulator call goes through the runner contract, which owns the backend (local, docker, ssh, lsf), environment (`env_source`, tool paths), license wait, timeouts and verdict capture.
3. **Configuration is consumed or removed.** Every `rat_config.json` field is read by the runner or dropped from the schema and docs.
4. **Prompts carry goals, contracts and reasons.** Exact scripts only where one sequence is safe.
5. **Measure before restructuring.** A plugin eval suite runs before and after every prompt or roster change.

## 4. Phases

**Phase 0 — Environment (no code).** Refresh the marketplace and update the installed plugin; update oh-my-claudecode (5.5.0 is available) or disable its SubagentStop tracker.

**Phase 1 — Enforcement integrity (2.0.0-alpha.1): F1, F2, F3, F8, #8, F4.**

Sub-plans: 1a `2026-09-25-v2.0.0-phase1a-hook-contract-plan.md` (F1, F8, Stop-gate breaker; written) · 1b slash-command parity (F2) · 1c consented template install and update channel (#8, F4) · 1d runner-written verification evidence (F3). F1 was confirmed live on 2026-09-25 (1a § Evidence).

- Switch Stop blocks to `{"decision":"block","reason":…}` and PreToolUse denies to a deny without `continue:false`; add a no-progress breaker so working blocks cannot loop; hand user decisions over with a `systemMessage` notice; rewrite the 39 assertions and the hook development guide.
- Register `UserPromptExpansion` for plugin skills, mirroring the PreToolUse(Skill) bookkeeping.
- rat-init-project: remove the installer from the hook; install as an explicit step after the user confirms; add `--dry-run`.
- Runners write `.rat/state/verify-evidence.json` (RTL content hash, verdict, log paths); `rtl-verify-stop-gate.sh` checks hash freshness instead of a touched marker.
- `rtl-edit-tracker.sh` stops deleting verification evidence on read commands: `git diff`/`git add`, `sed -n`, `make sim`, and simulator invocations that merely mention a `.sv` path currently delete `rtl-verify-done` and `rtl-verify-waiver` (Task 3 review, I3). Store tracked paths project-relative and drop `NAME=` prefixes; with hash-based evidence, only a content change can invalidate verification.
- Point the dead `TaskCreate` matchers at `Agent`.
- Update channel: bump all `rat-version` markers, add markers to `run_sim.sh` and the Makefile, add a test that fails when a template changes without a marker bump, and have rat-init-project offer `--update`.

**Phase 2 — Truthful verdicts (alpha.2): #10, #11, #16, #17, #18, F9, F10.**
- Shared verdict classifier (bash + Python): PASS / FAIL / HANG / TIMEOUT / STALL / INCONCLUSIVE from exit status, log signatures and a completion marker. The precedence rules are a domain decision — owner: maintainer.
- SpyGlass: `set_option enableSV12 yes` + `-type verilog`, `incdir`/`define` mapping, `</dev/null`, Tcl error trap with a completion marker, goal-summary parsing.
- Simulators: VCS `-exitstatus`, `$fatal` in TB templates, `+timeout` plusarg read, watchdog module (tick / hang / timeout), portable runner stall timeout (macOS has no GNU `timeout`).
- Synthesis: require a target library or an explicit opt-out (DC, Genus, PPA-Opt); align the Tcl-safety whitelist with the sibling wrappers.

**Phase 3 — Execution backend (alpha.3): #1, #2, #3, #12, #13, #14, F5, F6** — per the companion spec.
- Wrapper-level remote execution (sync once, run the whole wrapper remotely, fetch declared outputs); ssh and lsf backends; csh environment adapter.
- Export `RAT_PROJECT_ROOT`; one path canonicalization (logical).
- Tool-path variables in `config.mk` (`DC_SHELL ?=` …) consumed by the runner; license wait (`RAT_LICENSE_WAIT_MIN`, mapped per tool after checking vendor docs).
- Fix the Docker path mapping (identical mount path) or drop `docker exec`.

**Phase 4 — Capability-based setup (beta.1): #4, #5, #6, #7, #9, #15, F7.**
- Readiness by capability (at least one simulator, one linter, …); phase-scoped requirements (cocotb for func-verify, SystemC for P2/P3 BFM).
- Agents take tools from `preferences.*`; P5 functional verification routes to UVM when the preferred simulator is commercial.
- STA/power categories (`pt_shell`, standalone `pwr_shell`; Joules/Voltus/PowerPro keys) and a SAIF hand-off.
- `technology.db` vs `technology.liberty`; preserve user-entered NAND2 area; vendor cell patterns.
- `RAT_PYTHON` plus versioned probing; env-config seeding; preference refresh on regeneration.
- D4 configuration: `models.architecture` (`fable` | `opus`) in `rat_config.json`, asked by rat-init-project and, for projects initialized earlier, once at the first architecture-phase run.

**Phase 5 — Prompt and roster modernization (beta.2).** See the guide mapping.
- 5a. Eval suite first (`evals/`, `claude plugin eval`): routing cases in English and Korean, gate-behavior cases, refusal checks; baseline on v0.14.6.
- 5b. Shared-block rewrite (agent-lib templates + sync), description trims, `(Opus)` removal, model/effort per D4: `effort:` frontmatter on every agent, per-spawn `model` for the architecture tier read from `rat_config.json`, removal of the 20 `model="sonnet"` spawn overrides, and CLAUDE.md best-practice 11 (model policy) rewritten to match.
- 5c. Gate-as-code (`scripts/gates/`), replacing prose gate checks and deterministic wrapper agents.
- 5d. De-prescribe judgment agents; adopt the official Fable 5.1 / Opus 5.5 snippets where they fit.
- 5e. Roster and policy-skill consolidation per D2/D3 (breaking).

The D4 configuration surface lands in Phase 4 with the other `rat_config.json` schema changes: the `models.architecture` key and the initialization question.

Ordering rationale (D1): every later phase relies on hooks and verdicts for enforcement, so Phases 1 and 2 come first; Phase 3 follows. Phase 5 must follow its own eval baseline.

## 5. Decisions

All four were decided by the maintainer on 2026-09-25.

| ID | Question | Decision |

| D2 | Policy skills (41 listed, non-user-invocable) | Inline each policy into the orchestrators that preload it, via sync scripts (the step0 pattern); keep the 4 convention skills (systemverilog, systemverilog-assertion, uvm, systemc) as skills |
| D3 | Roster consolidation | Merge the sequential/team orchestrator pairs behind a mode argument; replace `dc-report-parser` and `synthesis-reporter` with direct script calls; keep the domain experts |
| D4 | Model/effort policy | Architecture judgment: the latest Fable at max, chosen per project at initialization (Opus at max when the user picks Opus).
